## Goal

The uploaded `Product Slab Report.xlsx` has **267 product images embedded directly in column G**, one per product row. Extract them, map each to its product by row → item code, host them as Lovable Assets, and display them in the catalogue with no AI lookup required.

## Steps

1. **Extract & map** (Python script, one-off)
   - Unzip the xlsx and parse `xl/drawings/drawing1.xml` to get each image's anchor row + `rId`.
   - Resolve `rId` → `xl/media/imageN.png` via `xl/drawings/_rels/drawing1.xml.rels`.
   - Read `xl/worksheets/sheet1.xml` to map each anchor row → item code (column with `ITEM CODE`).
   - Produce `{ itemCode: imageFile }` mapping.

2. **Upload to Lovable Assets**
   - For each image: `lovable-assets create --file <png> --filename <itemCode>.png > src/assets/products/<itemCode>.png.asset.json`.
   - Skip if asset JSON already exists (idempotent re-runs).

3. **Wire into `ProductImage`**
   - Add a build-time `productImageMap: Record<itemCode, url>` in `src/lib/product-asset-map.ts` generated by importing all `src/assets/products/*.asset.json` via `import.meta.glob('@/assets/products/*.asset.json', { eager: true })`.
   - In `src/components/product-image.tsx`: if `productImageMap[product.itemCode]` exists, render that `<img>` immediately — highest priority, above DB AI-lookup result and above the SVG placeholder. AI lookup remains as fallback for SKUs without an embedded image.

4. **Verify**
   - Spot-check 4–5 product pages in the preview to confirm real photos show up.
   - Confirm catalogue grid loads (lazy-loaded images, no layout shift).

## Notes

- No DB changes. No new server function. Existing AI lookup stays as a fallback for the small number of SKUs that may not have an embedded image.
- ~267 PNGs at small dimensions (~100×100 px each) — light asset footprint.
- Item-code is the stable join key (already on every product in `src/data/products.ts`).
